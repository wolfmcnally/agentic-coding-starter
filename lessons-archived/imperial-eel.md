The four-role loop gives its critic a fixed target: the phase file states the approved scope before anyone writes code, so the review measures the work against something the reviewer did not have to infer. The direct-implementation route for methodology changes keeps the independent review but drops that artifact, and the reviewer is left reconstructing the approved outcome from whatever the dispatching agent chose to say.

That is a weaker review in a specific way. The dispatching agent writes the prompt, so scope drift it did not notice is invisible: the review can only check the work against the account of the work given by the party that did it. A separately written scope record removes that coupling for the price of a paragraph.

**Record the approved scope at the start of a direct-implementation run, not only at its close.** The route already requires recording approved scope, changed paths, verdict and gate results when the work closes; moving the scope half to the front costs nothing and gives the independent reviewer the same fixed target a phase file gives the critic.

**Graduated 2026-09-05 by operator ruling**, the same day it was filed. The rule landed in the direct-implementation route's own policy: the approved scope is written down before the work starts, as a block in the activity log under the log-discipline policy, and the independent reviewer is handed that record rather than a description composed afterward. Its first application was the very next change, where the reviewer confirmed that reviewing against a record written in advance was materially different from reconstructing one.
