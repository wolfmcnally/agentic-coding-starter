## 2026-11-10 — METHODOLOGY SCOPE

Authorized outcome (operator direction, this session): on macOS, the ignored runtime-state directory `.kickoff/` is marked excluded from Dropbox syncing automatically and permanently, whether or not the checkout is currently inside a Dropbox folder. The marking arrives with the shared toolchain helper, so this repository, newly stamped projects and every project that receives the helper through methodology transfer are marked on their next wrapper run without a separate step. Other platforms are out of scope: the repository has never been qualified there, and the rule is a no-op off macOS.

Mechanism: the shared helper that `setup`, `test`, `check`, `python`, `test-governance` and `mutate` initialise through creates `.kickoff/` and writes both documented Dropbox ignore attributes (classic-folder and File Provider forms; names verified against Dropbox's help page, updated 2025-10-07, retrieved 2026-11-09). A failed write on macOS is an error, not a silent skip.

Surfaces: `bin/_python-toolchain`; the toolchain entry-point test family and any proof-admission record it requires; `bin/README.md`; the manual's repository layout page; the build-gates policy's runtime-storage statement; `stamp` and `teach` transfer notes; release notes if the release policy requires an unreleased entry; ordinary immutable scope/close records.

Exclusions: recipient repositories (no transfer is run here), other sync services, non-macOS platforms, other ignored directories such as virtual environments, any Dropbox rules file, release tagging, product phases and independent review. Known consequence accepted by the operator's direction: Dropbox removes an already-synced `.kickoff/` from its server and other devices once the directory is marked, keeping the local copy.

Proof admission before authoring: the plausible failures are a refactor that drops the marking from the shared path and a mistyped attribute name, both silent because sync exclusion has no other observable effect in the repository. One behavioral check runs a real entry point in the existing fixture and reads both attributes back; it skips off macOS. No new family.
