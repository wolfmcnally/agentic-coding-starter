## 2026-11-15 20:41 — END — METHODOLOGY — Regeneration validates before it writes, a repeated registration is a no-op, and a run checks catalogs before capture

Scope: the operator's direction of 2026-11-15, relayed by the coordinator: "Make those methodology fixes. Also mention them to the Starter worker so it will incorporate them in its next release." This record covers the remaining three of the four fixes a consumer project found and qualified; the first, the early gate checks, has its own record. The consumer's implementation was read as a source and adapted, not copied: its tools sit on an earlier layout and two of them duplicate interfaces this template already has. No release.

Changed:
- Report regeneration. `check-execution-dashboards --regenerate` now collects every repair, validates the whole archive as it would stand afterwards, including the safety checks on the content about to be written, and only then writes. A handoff is treated as an input: one that differs from its rendering is refused and never rewritten. The trace ledger is never touched, and each report keeps the accepted trace it already names. Before, regeneration wrote each file as it found it, so a later failure left a half-repaired archive, and a differing handoff would have been overwritten.
- Catalog registration. `check-catalogs --register-input` on a document the catalog already lists now writes nothing and succeeds, whatever label or digest the repeat supplies. Before, it refused, which made a rerun after an interrupted delivery fail on work already done.
- Run start. `kickoff-evidence init` runs the checkout's own catalog check before it creates a run directory, freezes tools or captures authority, and refuses with that check's output when it fails. A missing checker also refuses.

Why: in the consumer project a cancelled attempt of an earlier phase was finalized into the trace ledger later, which changed that phase's already rendered report; only the newest report was regenerated, and the strict check refused the older one at the final gate, after a costly run. Its recovery also needed a catalog addition to be repeatable.

Not taken: the consumer's separate reconcile flag and its heading-and-label catalog flag. Regeneration and registration already exist here, so only the missing behavior was added. Crossing a report payload schema change is still not supported; that earlier lesson stays open.
