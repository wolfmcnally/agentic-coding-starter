## 2026-11-10 10:50 — END — METHODOLOGY — Teach: maintenance transfer of a migrated recipient to release 1.4.0

Scope: an operator-approved maintenance `teach` bringing a recipient from release 1.0.2 to 1.4.0. This repository was read-only; this entry is its only change.

Outcome: the recipient's owner declaration was recorded with `multioperator adopt`; its two-language gate and test entry points were merged with reuse, report mode and parallel execution while keeping its native lanes; its proof estate moved to schema v5 with 35 proofs admitted in one batch and two retired; its report pages were re-rendered with the current dashboard. Its full gate passed in its own checkout and the change was pushed by fast-forward. The preflight now reports maintenance with no releases unrecorded.

Found: the recipient's first full gate in its own checkout failed seven proofs because parallel workers started a script-environment tool while that tool's cached environment was being built for the first time. A second run on the unchanged tree passed. The first failure was disclosed to the operator before the push. A push attempted by a chained command after the failed gate was refused by the recipient's push check; nothing was published from the failed run.

Lessons:
- Parallel test workers can race the first build of a script tool's cached environment. Proposed for the operator's decision, not yet filed or fixed: have the test entry point build those environments once before starting workers.
- A delivery command must read the gate's exit status before it reaches a push; chaining the push after an unchecked gate relied on the recipient's hook to stop it.
- The dashboard's regenerate command cannot convert report inputs from an earlier payload schema; a recipient crossing that boundary needs a one-time re-render from its traces. Proposed, not yet filed.
