## 2026-11-22 04:56 — END — METHODOLOGY — Release 1.10.0 prepared: no elapsed limit ends a test

Scope: the operator's direction of 2026-11-22, relayed by the coordinator: "I think it was a bad call to let Starter dictate wall clock times for any tests. I want it to encourage minimal wall clock times for running tests after changes but hard limits with aborts were never my intent. We should probably fix this in Starter first, do a release, and then teach it from starter to our active repos". One bounded change, its proofs and its release notes. No recipient and no other repository was touched.

Cause: the test supervisor ended every test command at a deadline read from the proof manifest, 1800 seconds by default, and the template's own nested fixtures declared 20 and 5 seconds. In a recipient on a loaded machine, the parallel fixture ran all five cases to a pass in a little over 20 seconds and was reported incomplete. The fixture is the template's, not a recipient adaptation. The one incomplete status and one message covered an elapsed deadline, a cancellation, a signal death and a leftover child alike, so the report could not say which had happened. The written policy already called ordinary durations diagnostic; the shipped behaviour disagreed with it.

Inventory and ruling on each clock found:
- Removed, because the template imposed them on ordinary tests: the supervisor's deadline and its default; the manifest key and its validation; the manifest values in three fixtures; the outer helper deadline and the five-second rendezvous in the parallel fixture; thirty-six helper timeouts on ordinary tool calls across seventeen test files; clocks on fixture readiness in the tests rewritten here.
- Kept, because time is their subject: waits for a process to stop after a signal or cancellation; the role watcher's own first-event, idle and hard clocks and the tests that prove they fire; the opt-in mutation survey's budget and per-fault limit, which report a partial survey and never gate; cleanup graces, which begin only after a cancellation or an established leftover child.
- Left alone as another subject, and reported: the documentation tool's limit on its own commands, version and status probes, and the optional operator-supplied limit of the telemetry runner.

Changed:
- `run_command` has no deadline parameter. A completed command keeps its own exit status however long it ran. The incomplete status remains for a cancelled run, a command ended by a signal, a command that exits and leaves a member of its process group running, and a descendant outside the group that still holds the captured output; each names its reason, and the leftover-child reason names the command's own status.
- Captured output is read by the supervising thread without a clock. A pipe reports its end only when every writer has closed it, so once the command and its group are gone one read separates finished output from output another process holds. An orphan that keeps the output open can therefore no longer hide a leftover child, and no timed drain can mistake a slow read for an open pipe. The first draft used reader threads joined against a two-second limit; the coordinator's read-only cross-check pointed out that a delayed reader and an open pipe were indistinguishable there, and the draft was replaced before any gate.
- Cancellation is also read after each wait on the output, because this platform's selector absorbs an interruption raised inside it; the first run of the rewritten proofs caught that as a cancelled run that did not return.
- Validation refuses a manifest that still declares the retired key and says to remove it.
- Policies, briefs and the stamp, teach and learn skills state the ruling, the retained clocks and the one-line manifest removal a recipient makes.

Proofs: eleven admitted, three modified and eight retired in one admission, each new or changed proof observed red against a planted defect and green on restoration, first in a disposable clone and then here. They establish: a command outlasting the earlier limit finishes with its own status through the real entry point; a completed error keeps its status; TERM, repeated TERM, HUP and operator interruption are incomplete, name the signal and remove a child that ignores TERM; a leftover child is reported at once with the leader's status whether or not it holds the output; an escaped holder of the output is named and a 300,000-byte backlog on each stream is returned whole; governance leaves a nested supervisor time to clean up; a cancelled parallel run removes its workers; the retired manifest key is refused. Three planted defects first disabled the witnessing run itself rather than the fixture and were narrowed in rehearsal.

Release: `RELEASES.md` gains the 1.10.0 entry and transfer list. Minor increment: a methodology behaviour change with a retired manifest key, classified as the removal of turn caps was in 1.8.0.

Verification: the two changed test files, the changed-path selection (widened to the full suite), then the release gate with every proof run on the exact tree.

Remaining: recipients take the release through `teach`. Each deletes the retired manifest line, removes any `timeout=` it passes to the supervisor, admits the arriving proofs and audits its own tests for helper timeouts on ordinary work.

Lessons:
- A safety deadline is still a verdict-changing clock. The policy said durations were diagnostic while the supervisor turned a slow pass into an incomplete run; prose and behaviour were never checked against each other, and the deadline's fixture values were tuned to one machine.
- One status with one message for four causes hid the cause from the first report. A reserved status needs a named reason at the point it is produced.
- A witness plant in the test supervisor can disable the run that is supposed to observe it. Plants there must bite only the fixture.
