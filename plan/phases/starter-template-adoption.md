# Adopt the template for your project

This is an unstarted placeholder for a new project's first concrete outcome, not a completed product phase. The canonical event chain retains its imported next selection. Stamping a different project does not prove acceptance of this phase.

## Goal

Turn the template into a project with its own brief, permanent phase definitions, lifecycle records and first working slice. For a separate new directory use `/stamp <directory> <description>` in Claude Code or `$stamp <directory> <description>` in Codex. The receiving project gets its own initial records and proof judgments rather than this template's history.

To develop in this checkout, replace this placeholder's narrative with the real outcome and acceptance criteria while retaining its permanent identity, or add a separately authorized phase with `bin/multioperator add`. Update titles, dependencies and rational ordering in phase definitions; keep state and custody solely in lifecycle events. `plan/INDEX.md` remains discovery context.

## Decomposition

Use the real outcome's consequential boundaries. JIT sub-phases receive permanent three-word ids, parent references and explicit lifecycle records; they are not renumbered as execution order changes.

## Deliverables

- A concrete [project brief](../../briefs/BRIEF.md) with product scope, acceptance and dependencies.
- Phase definitions and context that describe the real project, with one unambiguous event chain per phase.
- A working first product slice and the atomic runtime, lockfile, wrappers and tests for its actual language and surface.
- Project-local proof inventory and retained evidence; no copied donor judgments.

## Acceptance

- The [bootstrap acceptance contract](../../briefs/agentic-bootstrap.md) holds for a stamped project.
- `kickoff` selects the intended permanent phase under actual coordinated ownership; active work is explicitly named for resume.
- Setup, focused and changed-path tests, acceptance and final full gates pass under the current methodology.
- Completion uses genuine accepted phase evidence and current owner/claim joins. A manually changed discovery file or imported next marker is not acceptance.
- The operator's product/demo and native instruction-loading criteria remain separate and truthful.
