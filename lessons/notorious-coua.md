A phase that derives its work set from a command gets a completeness guarantee for
everything the command can see. That guarantee is worth having, and it is
precisely what makes the exceptions dangerous: **the items outside the derivation
are now the only items with no mechanical backstop**, and they sit in prose in the
middle of a plan that is otherwise self-verifying.

The failure is not inattention. It is that a derived plan trains everyone —
planner, coder, reviewer, orchestrator — to trust that re-running the command
proves the work complete. It does, *for the derived set*. The carve-out is
invisible to exactly the check everyone is relying on, and the sentence naming it
reads like context rather than like a task.

**The cheap fix is structural, not attentional.** When a plan names a change the
derivation cannot re-surface, that change gets its **own line** in a checklist the
close actually walks — not a sentence inside a paragraph of modified files. One
line per underivable item, verified individually, because it is by construction the
item no sweep will find again.

**Corollary from the second occurrence: a checklist only backstops what was
written into it.** An agreement reached in conversation is *unfiled* until it is a
line in the file — and a context compaction preserves task state while shedding
exactly this kind of unfiled agreement. That is why this repo's continuation-packet
discipline treats "what was agreed but not yet written down" as the first thing to
transcribe at a seam.
